# 技术决策：Android 客户端与云端持续采集

日期：2026-11-17。状态：用户已确认技术方向，尚未实施。

## 已选方案

使用 Vue 3 + TypeScript + Capacitor 制作 Android APK；云端使用 Python + FastAPI + SQLite，图片保存到服务器持久磁盘；使用 Docker Compose 部署，以 Caddy 提供 HTTPS 接口。

首版只做 Android App，无需独立电脑网页界面或应用商店上架。采集程序和后台均在云端常驻，手机关机不影响采集。QQ 接入先验证，B 站接入后置。

普通图片默认保留 5 天，收藏长期保留；共享文件在全部普通来源过期且未收藏时回收。手机缓存和主动保存到相册的副本分别管理。

## 理由与替代方案

- 相比本地桌面工具，云端持续采集满足电脑关机仍能收图的要求。
- 相比浏览器入口，Android APK 满足用户直接打开手机应用的偏好。
- 相比 Flutter 或 Kotlin 原生首版，Vue + Capacitor 适合目前以图库、筛选和编辑为主的范围，减少单独学习和维护手机界面的成本；代价是需专门验证 WebView 长列表、大图手势和原生插件。
- 单人、单机范围先用 SQLite，避免提前引入数据库服务、Redis 和分布式任务系统；需要多实例时再评估迁移。
